# 색인(찾아보기) 설계 메모 — 원서 목록 → 번역본 쪽 채움

- 날짜: 2026-08-25
- 상태: **1차 목표 축 합의 · 입력 형식/로케이터 문장 고정 직전**
- 구현: 없음 (설계·사실관계만)
- 관련: `editingbears 찾아보기`(AI), `반자동 색인 편집기 1.12`, 인디야 표기 통일·공통 항목 찾기
- 실측 스크립트: `scripts/_probe_index_locator_hits.mjs` (4교 199쪽)

---

## 1. 전제 (업무)

- 대상 책의 **약 90% 이상은 외서 번역**으로 본다.
- 편집자·번역자가 가장 먼저 손에 두는 것은 보통 **원서 찾아보기(영문 등)** 이다. (답: A)
- 따라서 색인의 중심 업무는 「한국어 PDF에서 후보를 새로 뽑기」가 아니라  
  **원서 항목을 이 번역본에 이식하기** 이다.

```text
원서 인덱스 항목
  → (사람이) 한글 표제어·채택/탈락
  → 번역본 PDF에서 쪽수 채움
  → 가나다·내보내기
```

세 단계 중 인디야가 이미 강한 구간은 **쪽 채움(본문 find·하이라이트)** 이다.  
표제어 선정·번역 표기는 사람(또는 나중 단계)의 일이다.

---

## 2. 세 방식과 인디야의 위치

| | AI 찾아보기 (editingbears) | 반자동 색인 편집기 | 인디야 재사용 시 |
|---|---|---|---|
| 색인어 출처 | 모델이 PDF에서 생성 | 사람 파일·수동 | **사람이 정한 한글 표제어 목록** |
| 쪽수 확정 | 서버 일괄 | 클릭마다 기입 | **find로 쪽 후보 일괄 → 사람이 걸러** |
| 강점 | 목록 없이 맡김 | 편집 통제 | PDF 텍스트·match·하이라이트 인프라 |
| 약점 | 과금·블랙박스 | 클릭 노동 | 통일=이형태만, 공통=등록 후만 → **색인 적격성 정책은 없음** |

한 줄:

- AI = **생성**
- 반자동 = **매핑 가속**
- 인디야 = **매핑은 강하고, 생성은 거의 없음** → 외서(원서 목록 보유)와 맞음

### 왜 C(A 기본, B 나중)인가

이전 선택지:

- **A** — 색인어 목록을 사람이 연다 → 쪽수만
- **B** — PDF만으로 후보 생성 → 사람 선별 → 쪽수
- **C** — A를 기본, B는 나중

C로 좁히는 근거는 “먼저/나중”이 아니라 **질적 차이**다.

> 통일은 이형태만, 공통은 등록 후에만, **색인 품질 정책(무엇을 올릴까)은 새로.**

- **A**는 선정이 밖에서 끝나 들어오므로, 그 신규 영역이 **발생하지 않는다**. 기존 스코프(찾기·쪽) 안에 남는다.
- **B**는 후보 생성을 맡는 순간 **색인 적격성**이라는 새 제품 판단을 요구한다.

지금까지 지켜 온 「스코프를 얇게 잠그고 확장은 별도 단계」와 같은 결이다.

## 3. 1차 목표 축 (합의)

사용자가 편하면서 인디야로 구현 가능성이 큰 중심:

```text
사람: 원서 인덱스 → 한글 표제어 목록
인디야: 각 표제어를 번역본 PDF에서 찾아 쪽 목록 제안
사람: 엉뚱한 쪽/히트만 빼기 · 없는 항목 보류
인디야: 내보내기 (표제어 + 쪽)
```

- 반자동처럼 매 히트마다 쪽을 찍지 않음.
- editingbears처럼 색인어를 AI가 새로 뽑지 않음.

### 층 나누기

| 층 | 내용 |
|---|---|
| **1차 추천** | 위 축 (목록 → 쪽 후보 → 걸러 내보내기) |
| **확장 후보** | 아래 §5 |
| **지금 미룸** | PDF만으로 후보 생성(B), 원서쪽→번역본쪽 자동 대응, 영문→한글 번역 제안, 영문 문자열 본문 직접 찾기(주력 제외) |

### 금지 (스코프 누수)

- 통일 **1차/2차 UX** · Preview 문 · Kiwi/SLM을 색인 1차에 태우지 않음.
- 출력의 **가나다·쪽 범위 포맷**은 출력 단계 신규로 분리.
- **`rawByKey` / 표기통일 파이프라인 → 색인 쓰기 방향 의존 금지.**  
  이형태 힌트가 필요해져도 **참조만**. 통일 축(문서 내부 쌍 비교)과 색인 축(외부 표제어 찾기)을 데이터 레벨에서 얽히게 하지 않음.

## 4. 사실관계 (코드 + 4교 실측)

샘플: `260107_스트리트 이코노미-본문(4교).pdf` 199쪽.  
스크립트: `scripts/_probe_index_locator_hits.mjs`.

### 4.1 `findPhraseHitsInPdfItems` / literal find가 잡는 범위

| 경로 | 조사 결합 (`경제`⊂`경제는`) | 복합 연장 (`경제`⊂`경제학`) | 띄움↔붙임 |
|---|---|---|---|
| `findPhraseHitsInPdfItems` | glue **부분문자열**로 잡힘 | 같이 잡힘 | `spacingFidelity` — **서로 안 통함** |
| `runRuleCheck` literal | 부분문자열 | 부분문자열 | 별 find |
| `countHangulSurface` (spike) | 어절+조사로 의도적 | 조사 아니면 보통 제외 | 표면 단위 |

**순수 literal/item find만으로 「쪽수만」을 끝낸다고 쓰면 과하다.**

실측 요지:

| 표제어 | item 히트 | 등장 쪽 | literal 중 복합어형 추정 | 비고 |
|---|---:|---:|---:|---|
| 경제 | 629 | 152 | ~44% | 짧은 일반명 — **정밀도** 문제 |
| 시장 | 400 | 120 | ~10% | |
| 주식시장 | 49 | 25 | ~7% | 긴 말은 쪽 후보로 쓸 만함 |
| 경제성장 | 39 | 27 | ~17% | |
| 경제 성장 | **0** | 0 | — | 붙임만 있으면 띄움 needle은 전무 |
| 인플레이션 | 214 | 67 | ~9% | |
| 연방준비제도 | 10 | 8 | ~9% | |
| 케인즈 | 0 | 0 | — | 표기 불일치·미출현 가능 |

분기 (1차 vs 나중):

| | 1차에 넣을지 |
|---|---|
| raw `findPhraseHitsInPdfItems`만 | **부족** (짧은 말·띄움) |
| **쪽 단위 병합** + 히트 뒤 한글 연속(복합) 거절·조사만 허용 | **1차 얇은 로케이터**로 넣을 가치 큼 |
| 띄움↔붙임 자동 쌍 | 목록에 두 줄 **또는** 아주 얇은 쌍 규칙. 통일 `rawByKey` 연결 금지 |
| 통일 discover/UX | 1차 금지 |

조사 결합 “재현”은 부분문자열 부작용으로 이미 잡히는 경우가 많다.  
1차에서 더 급한 것은 **복합어 과매칭 억제**와 **쪽 병합**이다.

### 4.2 「엉뚱한 히트만 빼기」UI

`경제`만 item 히트 629 · 쪽 152 · 한 쪽 최대 19.  
공통 항목식 **히트 한 줄씩 체크**는 일반 색인어 규모에서 버겁다.

1차 UI 전제:

```text
기본 단위 = 표제어 → 쪽 목록 (중복 쪽 병합)
히트 단위 삭제 = 보조(펼치기), 기본 조작 아님
```

쪽 병합을 전제할 때만 「기존 목록형 UI로 감당」이 성립한다.

## 5. 확장 후보 (1차 다음)

1. **표제어 옆 “본문에서 찾기” 원클릭** — 집계·내보내기 없이 네비만 하면 반자동과 노동량이 비슷해질 수 있음.
2. **같은 표제어의 띄움/붙임만 묶어 보여 주기** — 쪽 채움 **보조**.  
   통일 UX 재사용 금지. `rawByKey`는 참조만·쓰기 의존 없음 (§3 금지).
3. **원서 영문 문자열을 번역본에서 직접 찾기** — 고유명 잔존 책에선 보조. 개념어는 들쭉날쭉 → **주력 제외**.

## 6. 아직 문장으로 못 박지 않은 것 (다음 단계)

실측(§4)으로 전제는 뒷받침됨. 다음에 **한 블록**으로 고정할 항목:

1. **입력 형식** — 권고안: 텍스트, 한 줄 = 하나의 한글 표제어 표면형. 화면 추가는 보조. spelling_rules/공통 규칙 시트 재사용은 A에 섞지 않음. 엑셀은 나중.
2. **1차 로케이터 문장** — raw find + 복합 연장 거절(조사만 허용) + 쪽 병합. 이형태 자동 확장은 1차 밖 또는 “목록에 두 줄”.
3. **내보내기 최소 스키마** — 표제어 + 쪽 목록(정렬·범위 표기는 출력 단계).

이 문서 승인·위 세 줄 고정 전에는 구현에 들어가지 않는다.

## 7. 인디야 모듈과의 거리 (재사용 지도)

| 쓸 것 (찾기 층) | 쓰지 말 것 (1차) |
|---|---|
| `runRuleCheck` / literal·phrase 인프라 | `UnifyCandidateFindPanel` UX·phase2 |
| `findPhraseHitsInPdfItems` (로케이터 위에) | Kiwi/SLM/Preview publish·remap 문 |
| 페이지 하이라이트 헬퍼 | 색인 적격성·AI 후보 생성 |
| (참고만) orthography spike의 어절·조사 감각 | 통일 `rawByKey` → 색인 상태 쓰기 |

레포에 **책 뒤 색인/찾아보기 전용 기능은 아직 없음.** (`toc-body`는 목차↔본문 검사용)

## 8. 한 줄 요약

외서 번역 색인 1차는 **원서에서 고른 한글 표제어 목록 → 번역본에서 쪽 후보(얇은 로케이터·쪽 병합) → 사람이 걸러 내보내기** 이다.  
생성형 AI·통일 파이프라인 편입은 별 단계다.
