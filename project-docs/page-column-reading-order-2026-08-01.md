# 페이지 내 2단(column) 읽기 순서 (2026-08-01)

**상태:** 합의 · **구현됨** (`pageColumnSplit.js`)  
**관련:** `spreadColumnSplit.js`(펼침면) · `pdfPageText.js` · `visual-semantic-text-layers-2026-08-02.md` (§12 PDF.js raw vs visualText 비교) · `hangul-soft-wrap-rejoin-2026-08-01.md`(구 soft-wrap)

## 목표

교정 엔진이 받는 `page.text`에서, **본문 2단 때문에 단어가 가로로 붙는 오류**를 줄인다.

예 (교재·인문·학술서):

| 잘못 | 원인 |
|------|------|
| `초점냉대 기후` | 오른단 `초점` + 왼단 `냉대 기후` |
| `안냉대 기후` | 오른단 `안`(안정) + 왼단 `냉대 기후` |
| `집중온대 기후` | 오른단 `집중` + 왼단 `온대 기후` |

목표가 **PDF 레이아웃 완전 재현**이 아니라,  
**교정 결과를 망가뜨리는 명백한 읽기 순서 오류만 제거**하는 것이다.

---

## 주의: 펼침면과 분리

페이지 내 2단 감지는 **펼침면 감지와 별도 모듈**로 관리한다.

둘 다 “가로로 텍스트가 섞인다”는 현상은 같지만 **원인이 다르다.**

| | 펼침면 (spread) | 페이지 내 2단 (column) |
|--|-----------------|------------------------|
| 대상 | 두 페이지가 한 장 이미지처럼 들어옴 | 정상적인 **한** 페이지 |
| 목표 | **페이지 경계** 복원 | **읽기 순서** 복원 |
| 단서 | 페이지 폭이 비정상적으로 큼, 책등 | 페이지 안 세로 gutter, 좌우 본문 덩어리 |
| 모듈 | `spreadColumnSplit.js` | `pageColumnSplit.js` (본 설계) |

### 공통화 대상

- reading region 개념
- column ordering (왼 단 전부 → 오른 단 전부; **단 안에서만** y→line)

### 비공유 대상

- 감지 threshold
- page ratio 조건
- gutter 판단 기준

### 이유

펼침면은 **페이지 외부 경계** 문제이고, 2단은 **페이지 내부 레이아웃** 문제이므로 **오탐 방지 정책이 다르다.**

---

## 파이프라인

```
PDF item 추출
  → layout analyzer
       · 펼침면? → spread regions
       · 아니면 페이지 2단? → column regions (확실할 때만)
       · 아니면 단일 region
  → 각 region별 line build
  → soft-wrap · text 생성
```

이미 붙은 뒤에는 복구가 어렵다. **`buildPageText`의 줄 묶기 앞**에서 region을 나눈다.

하지 말 것: 전체 item에 column만 붙인 뒤 **전역 y sort** → 다시 섞임.

올바른 조립:

```
column 1: y 정렬 → line 생성
  ↓
column 2: y 정렬 → line 생성
```

## 감지 조건 (보수적 · 모두 만족)

히스토그램(가운데 빈 x) **단독으로 판단하지 않는다.**  
표·캡션·사이드바·인용 박스·머리말/꼬리말도 빈 공간을 만든다.

1. **gutter 비율** — `gutterWidth / pageWidth ≥ ~5%` (점선 단 구분 포함; 절대 pt 지양)
2. **좌우 텍스트량** — 양쪽 모두 충분한 아이템·문자 수
3. **라인 구조 독립** — 좌·우 각각 여러 y 밴드(본문 줄)가 형성됨
4. **gutter 띠에 글이 거의 없음**
5. **펼침면 후보가 아님** — 가로로 긴 스캔은 spread 모듈에 맡김
6. **후보 점수** — gap × 좌우 균형(아이템·문자·y밴드). 표 안 칸 경계는 균형이 낮아 탈락하고, 점수 비슷한 유효 후보가 여럿이면 격자로 보고 분리하지 않음

### 기본 정책

| 상황 | 동작 |
|------|------|
| 2단인데 1단으로 읽음 | 오류 발생 (지금 문제) |
| **1단인데 2단으로 나눔** | **본문 순서 붕괴 — 더 치명적** |

→ **확실할 때만 적용. 애매하면 기존(단일 region) 유지.**

## 범위 밖 / 후순위

- 표·박스 영역 정밀 제외 (후속)
- 3단 이상·잡지형 불규칙 다단
- soft-wrap (별도 문서, 이미 상당 부분 구현)

### ROI 우선순위

1. 페이지 내 명확한 2단 ← **본 문서**
2. soft-wrap 보완
3. 표/박스 영역 제외
4. 복잡한 다단·잡지형

---

## 테스트 (최소)

1. **교차 결합 방지** — 왼: 초점/안정/집중, 오른: 냉대·온대 기후 → `초점냉대` 등이 나오면 안 됨. 왼 단 문장 후 오른 단.
2. **표처럼 보이는 격자** — 열 간격이 좁거나 gutter 비율 미달 → **분리하지 않음**
3. **1단 긴 문서** — 기존 `buildPageText`와 동일(회귀)
