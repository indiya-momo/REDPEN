## 3. 기술적으로 알고 있는 점 (법무 판단 재료)

1. **WASM**: C++ 코어를 Emscripten으로 컴파일한 바이너리를 JS가 로드. LGPL의 “동적 링크 예외”가 **네이티브 .so/.dll** 전제인 경우가 많아, **WASM이 정적 링크에 해당하는지**가 쟁점.
2. 우리 앱(React 번들)과 kiwi wasm은 **별도 파일**로 로드할 예정(지연 로딩). 그러나 사용자가 받는 “제품” 단위로는 **함께 배포**.
3. 모델 파일은 wasm과 분리된 대용량 바이너리/사전.
4. 수정(derivative): 당장은 upstream 바이너리·모델을 **수정 없이** 사용. 래퍼는 우리 코드(`src/lib/kiwiMorph/`).

## 4. 법무에 묻고 싶은 것 (답변 요청)

### Q1. 적용 라이선스
- 우리가 npm `kiwi-nlp` + 공식 모델로 배포할 때, 준수 대상은 **LGPL-2.1-or-later**, **LGPL-3.0**, 둘 다, 또는 다른가?
- 코어 소스와 wasm 산출물의 관계가 “동일 저작물”인지.

### Q2. WASM과 LGPL “동적 링크”
- 브라우저에서 wasm을 로드·호출하는 구성이 LGPL상 **동적 링킹에 준하는 사용**으로 볼 수 있는가, 아니면 **정적 결합/결합 배포**에 가까운가?
- 그에 따라 **인디야 클라이언트(우리 코드)의 라이선스 의무**(소스 공개 범위, 재배포 조건)가 달라지는지.

### Q3. SaaS·원격 사용 (시나리오 C)
- 사용자가 wasm을 받지 않고, 서버에서만 Kiwi를 돌리면 LGPL 의무가 어떻게 달라지는지 (네트워크 사용·AGPL과의 혼동 방지 포함).

### Q4. 고지·제공 의무
- 웹앱 UI/설정/저장소에 넣어야 할 **최소 고지** 항목 (저작권, 라이선스 전문 링크, 소스 제공 방법).
- 사용자가 wasm·모델을 다운로드받게 될 때, **동일 배포물**에 라이선스 텍스트·소스 안내를 어떻게 붙이는 것이 안전한지.
- 소스 제공: upstream GitHub 링크만으로 충분한지, 우리가 쓰는 **정확한 버전 태그(0.23.0 / 모델 v0.23.1)** 고정이 필요한지.

### Q5. 모델 파일
- `kiwi_model_v0.23.1_base.tgz` 등 모델의 재배포·CDN 호스팅·사용자 기기 캐시가 허용되는지, 별도 조건이 있는지.

### Q6. 상용 SaaS와의 양립
- 인디야가 **유료 구독 SaaS**여도, 위 의무만 지키면 Kiwi를 **기능 플래그 ON 기본**으로 쓸 수 있는지.
- 쓸 수 없다면 **대안**(상용 라이선스 협의, 서버만 사용, Kiwi 미사용 유지) 중 권고.

### Q7. 지금 당장(시나리오 A만)
- 플래그 OFF + 저장소에 wasm을 dependency로만 두고 모델은 gitignore(`tmp/`)인 **현재 상태**도 배포(Vercel) 시 문제 없는지.
- `kiwi-nlp`가 `node_modules`/lockfile에 포함되어 프로덕션 빌드에 들어갈 수 있는 경우의 주의점.

## 5. 회신·채택 메모 (2026-08-02)

### Q3 — 시나리오 C (서버 전용) ✅ 배포 권장

> 클라이언트(브라우저)로 Wasm 바이너리를 전송하지 않고 **서버 내부에서만** Kiwi를 구동한 뒤  
> **결과(텍스트)만** 네트워크 API로 제공하는 경우,  
> LGPL(v3) 라이선스의 **소스코드 공개 및 재결합(Relinking) 의무는 발생하지 않습니다.**

### Q2 — 시나리오 B (브라우저 WASM) ✅ 해석·준수 조건

> 브라우저에서 JavaScript(또는 애플리케이션)가 WebAssembly(Wasm) 모듈을 **독립적으로 로드**하고  
> API를 통해 호출하는 구조는 **동적 링킹(Dynamic Linking)** 또는 **독립적인 모듈 간 연동**에 준하는 사용으로 해석됩니다.

동적 링킹으로 인정되더라도 LGPL 준수를 위해 **다음을 이행**해야 합니다:

1. **Wasm 라이브러리 소스코드 제공/공개**  
   해당 LGPL Wasm 바이너리를 만드는 데 사용된 LGPL 라이브러리의 원본(및 수정본이 있으면 수정본) 소스를  
   다운로드할 수 있는 **링크 또는 안내**를 제공해야 한다.
2. **저작권 및 라이선스 고지**  
   앱 내(서비스 정보·라이선스 안내 페이지 등)에 해당 Wasm 모듈이 **LGPL**임을 명시하고  
   **라이선스 전문**을 포함해야 한다.
3. **역공학 금지 조항 제한**  
   사용자가 LGPL 모듈을 디버깅·수정하기 위해 해당 부분을 **역공학하는 것을 금지하는 약관**을  
   적용해서는 안 된다.

**제품 함의**

| 경로 | 방침 |
|------|------|
| **C 서버 API** | **배포 기본 경로.** wasm 미전송 → Q3상 소스 공개·Relinking 의무 없음 |
| **B 브라우저 WASM** | **가능하나** 위 1~3 준수 필수. 배포에 쓸 경우 고지·소스 링크·약관 점검 후 |
| **A 로컬 DEV** | 개발자 PC/`tmp` · 테스트 유지 |

현재 엔지니어링 우선순위: **C 서버 API 구현**. B는 고지/약관 준비 전까지 프로덕션 기본 OFF.
