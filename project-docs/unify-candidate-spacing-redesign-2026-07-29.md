# 표기 통일 후보 찾기 — 띄어쓰기 이형태 (재설계)

**상태:** 1단계(발견·다수형) 구현됨 · 배포는 `VITE_FEATURE_UNIFY_CANDIDATE_FIND`로 숨김 · 추천 고도화는 후속  
**날짜:** 2026-07-29 (로드맵 §11 추가)  
**범위:** `src/lib/unifyCandidateDiscover.js` (+ UI·플래그). ruleEngine / 맞춤법 매칭 변경 없음(1단계).

---

## 1. 문제

현재 후보는 PDF 조판·추출 아티팩트를 많이 잡는다.

| 원하지 않는 것 | 원하는 것 |
|----------------|-----------|
| `있다` vs `있 다` (줄바꿈·음절 단위 간격) | `금융위기` vs `금융 위기` |
| 1음절 조각 나열 | 의미 있는 어절·합성어 띄어쓰기 혼재 |

원인: 페이지 텍스트를 한글·숫자 토큰 n-gram으로 이어 붙이며, **줄바꿈·글리프 간격으로 생긴 공백**과 **저자 의도 띄어쓰기**를 구분하지 않음.

---

## 2. 합의된 방향

1. **PDF 스캔 전처리**로 줄 경계 아티팩트를 줄인다.  
2. **띄움 variant 필터**: 공백으로 나눈 **각 덩어리 한글 2음절 이상**.  
3. 기존 정책 유지: NFC, 연속 공백→1칸, 키=공백 제거, 붙임+띄움 동시 존재, 추천=다수형/동률 시 붙임, 찾기=표기 통일 검수권 1회.

---

## 3. PDF 텍스트 전제 (이 앱)

`buildPageText` 결과:

- **시각 줄과 줄 사이**는 `\n`으로 이어진다.
- **같은 줄 안** 공백은 아이템 x간격으로 삽입된다. 양쪽 정렬(justify)·음절 단위 글리프면 **저자가 띄지 않은 자리에도 공백이 생길 수 있다.**

따라서 「줄바꿈 앞뒤 공백 = 의도된 띄움」만으로는 부족하다. 아래 전처리·필터로 보완한다.

---

## 4. 스캔 단위 — 줄바꿈 이형태 전부 제외

`buildPageText` 결과:

- **시각 줄과 줄 사이**는 `\n`으로 이어진다.
- **같은 줄 안** 공백은 아이템 x간격으로 삽입된다 (`text`는 자간에도 공백 가능, `textLayout`은 넓은 어절 gap만).

### 4.1 정책

**줄바꿈으로 생긴 붙임/띄움 이형태는 후보에 넣지 않는다.**

구현: 페이지를 `\n`으로 나눈 **뒤, 각 줄 안에서만** 토큰·n-gram을 만든다.  
줄 끝↔다음 줄 앞을 이어 붙이거나(`있`+`다`→`있다`), 공백으로 바꾸지(`수도`+`있다`→`수도 있다`) 않는다.

| 추출 | 처리 |
|------|------|
| `있\n다` | 줄별 `있`, `다` — 클러스터 없음 |
| `수도\n있다` | 줄별 `수도`, `있다` — `수도있다`/`수도 있다` 가짜 없음 |
| 같은 줄 `금융 위기` + `금융위기` | 후보 가능 |

### 4.2 textLayout

스캔 소스: `page.textLayout` 우선(없으면 `text`). 자간 가짜 공백(`인플레이 션을`) 완화.

### 4.3 알려진 잔여 리스크

같은 줄 justify/글리프 간격 오탐은 textLayout으로 대부분 완화. 좌표 기반 완전 제거는 범위 밖.

---

## 5. 띄움 variant 유효성 (덩어리 규칙)

띄움이 있는 variant만 검사. `normalizeUnifyVariant` 후 공백으로 split.

### 5.1 한글 음절 수

- 덩어리의 **한글 음절(가–힣) 개수**만 센다.  
- **숫자·영문·기호는 음절 수에 넣지 않고, 최소 음절 면제도 하지 않는다.**

### 5.2 통과 조건

각 덩어리: `hangulSyllableCount(chunk) >= 2`.

| 덩어리 | 한글 음절 | 결과 |
|--------|-----------|------|
| `금융` | 2 | 통과 |
| `위기` | 2 | 통과 |
| `있` | 1 | 탈락 |
| `제1차` | 2 (`제`+`차`) | 통과 |
| `1차` | 1 (`차`) | 탈락 |
| `2024` (숫자만) | 0 | 탈락 |
| `A` / `AI` 등 영문만 | 0 | 탈락 |

한 덩어리라도 실패하면 **그 띄움 variant 전체 무효**.  
유효 띄움 variant가 0개이면 **클러스터 제외**.

### 5.3 이중 역할 (명시)

이 필터의 목적:

1. **줄바꿈·글리프 오분절 제거** (`있 다` 등).  
2. **1음절 부정부사+용언 등 의미 분기형 자동 회피**  
   - 예: `안되다` / `안 되다`, `못하다` / `못 하다`  
   - 의미가 달라질 수 있어 문서 내 다수결 통일에 부적합 → **후보에 안 뜨는 것이 의도**.  
   - 나중에 「왜 후보에 없나?」→ 이 절을 안내.

---

## 6. 클러스터·추천 (1단계 — 현재)

유지·구현됨:

- 키 = 공백 제거 NFC 문자열.  
- **붙임형(공백 없음) ≥1** 그리고 **유효 띄움형 ≥1** 일 때만 후보.  
- 추천: 출현 수 최대, 동률 시 붙임 우선 (**규범 아님**, 문서 빈도).  
- 소수형만 페이지 칩 → 원고 이동.  
- 찾기 = 표기 통일 검수권 1회.  
- 「표기 통일하기 등록」으로 수동 통일 규칙에 연결.

**다수형 = 출발점**이지 최종 정답이 아니다. 고도화는 §11.

---

## 7. 「제1차세계대전」계열 — 별도 분기가 아님

성공 기준의 「제1차세계대전 계열 유지」는:

- **특별 케이스 코드/예외 처리가 아니다.**  
- §4–§6 일반 규칙을 통과하면 후보다.  
- 예: `제1차세계대전` vs `제1차 세계대전` — 띄움 쪽이 `제1차`(한글 2)·`세계대전`(4)이면 통과 가능.  
- 통일 추천도 일반 다수형/붙임 동률 규칙과 동일. 「후보만 뜨고 추천 안 함」이 아님.

## 8. 범위 밖 (1단계)

- AI·사전·맞춤법 규범으로 맞는 띄어쓰기 판정.

- PDF 좌표로 justify 공백을 완전 제거하는 추출기 개편.  
- 숫자·단위·기호 통일 (별도 설계).

## 9. 성공 기준 (1단계 테스트)

| 입력 요지 | 기대 |
|-----------|------|
| `있다`와 줄바꿈/`있 다`만 혼재 | 클러스터 **없음** |
| `금융위기` + 줄 중간 `금융 위기` | 클러스터 **있음**, 추천은 다수형 |
| `금융 \n위기`만 있고 붙임형 없음 (접합 후 붙임만) | 띄움 소실 → **없음** 가능 |
| `안되다` / `안 되다` | **없음** (1음절 덩어리, 의도적) |
| `제1차세계대전` / `제1차 세계대전` | 일반 규칙으로 **있을 수 있음** |
| 덩어리 `2024`만 있는 띄움 | 해당 variant **무효** |

## 11. 후속 로드맵 — 추천 고도화 (구체화할 기능)

**목표:** 다수형을 출발점으로 두고, **프로젝트·규범 방향**과 **문서 내 같은 계열 습관**으로 통일형을 다시 제안한다.  
**원칙:** 1차는 **규칙·집계**. AI는 애매 경계용 보조(필수 아님).

### 11.1 추천 근거 계층

| 층 | 근거 | 예 |
|----|------|-----|
| A. 쌍 다수형 | 이 클러스터 출현 수 (현재 1단계) | `살펴 보면` 12 / `살펴보면` 3 → 다수형 `살펴 보면` |
| B. 규범·기준 검수 | 본+보조용언 붙이기 등 **이미 있는 규칙**과 대조 | 다수형이 띄움인데 본+보조 붙임 방향과 충돌 → 「다수형이지만 붙임 방향과 어긋납니다. `살펴보면`으로 통일할까요?」 |
| C. 계열 경향 | 같은 앞말·패턴 클러스터들의 붙임/띄움 비율 | `경제전망` 붙임 우세 + `경제 성장` 띄움 다수 → 「경제○○은 붙이는 쪽으로 맞출까요?」→ `경제성장` |

UI: 추천 옆에 **근거 한 줄**(다수형 / 본+보조 / 계열 경향). 확정은 「하나로 통일할까요?」로 사용자 확인.

### 11.2 본+보조와 다수형 충돌 (층 B)

- 다수형이 `살펴 보면`이어도, 보조용언·본+보조 목록에 해당하면 **붙임형(`살펴보면`)을 대안 추천**.  
- 메시지 요지: 문서 다수형 ≠ 붙임 기준 → 충돌 안내 후 선택.  
- ruleEngine 매칭 로직을 바꾸지 않고, **후보 UI·추천 레이어**에서 기존 규칙 데이터를 읽는다.

### 11.3 같은 앞말 계열 (층 C)

- 예: `경제` + 뒤 성분(`전망`, `성장`, …) 클러스터를 묶어, 문서 전체의 붙임 비율이 높으면 **띄움 다수 클러스터에도 붙임 통일 제안**.  
- 「경제○○」처럼 **편집자가 말하는 책 안 습관**을 시스템이 말로 꺼내는 단계.  
- 앞말 길이·최소 클러스터 수·고유명 예외는 구현 시 스펙으로 확정.

### 11.4 발견 → 확정 흐름 (제품)

1. **발견** — 띄어쓰기 이형태 + 페이지 (1단계, 검수권 1회).  
2. **추천** — A→B→C 순으로 통일형 재제안 (이 절).  
3. **확정** — 통일하기 등록·핀·찾기/바꾸기, 또는 후보에서 바로 「확정」.  
4. **전달(유료 후보)** — 리스트·내보내기·표시 PDF (화면 복사는 맛보기 누수; 산출물이 유료 경계).

표기 통일하기 수동 입력은 **예외·미리 등록·비띄어쓰기 이형태**용으로 유지.

### 11.5 AI

- **필수로 넣지 않는다.** 층 B·C는 목록·집계로 충분.  
- AI 후보 영역: 합성어 경계 애매, 인용·고유명 예외, 설명 문장 다듬기.  
- 도입 시에도 **규칙 판정을 덮어쓰지 않고** 보조 힌트만.
