# 검수 결과 내보내기 · 원고 TXT 로드맵

**작성:** 2026-11-17  
**상태:** ① 주석 PDF 보류 · ② TXT 줄바꿈 확인 → 최종 받기 착수 (검수전 추출 + 확인 모달).  
**범위:** PC 메인 worktree. 서버로 원고를 보내지 않는다.

---

## 0. 목표와 사용자

| 사용자 | 필요한 출구 |
|--------|-------------|
| PDF 표시만으로 충분한 경우 | 주석이 달린 PDF 교정본 |
| 1인 출판·편집자가 인디자인까지 잡는 경우 | PDF 교정본 + (나중) 확정 쌍만 디자이너에게 |
| 원고를 다른 도구로 넘기는 경우 | 편집자·외부용 본문 TXT |

공통 최소 출구는 **주석 PDF**.  
인디자인 표·스크립트와 “완성 원고급 TXT”는 그 위 선택 출구다.

**이미 있는 것**

- 검수 결과 **엑셀** — 편집자용 검토표. 그대로 둔다. PDF/TXT로 대체하지 않는다.
- 업로드 화면 **TXT 변환** — 머리말·쪽수 제거 후 줄바꿈 확인 모달 → 최종 `….txt`. 검수전(`_검수전`, 쪽 표식)은 모달에서 선택 받기.

---

## 1. 전체 순서 (이 순서를 어기지 않는다)

```text
① 주석 PDF 좌표·뷰어 시험
    → 합격 후 주석 PDF 내려받기(제품)
② TXT 1차: 머리말·쪽수 제거 + 화면 검수 후 받기
③ (선택) TXT 2·3차: 역할·문단·캡션 등
④ 인디자인: 확정 쌍 TSV + 스크립트 하나
```

①의 좌표 파이프라인이 ⑤ 검수 UI(상자 하이라이트)와 같으므로, TXT 화면 검수보다 **주석 시험을 먼저** 한다.

---

## 2. 단계 ① — 주석 PDF 내려받기

### 하는 일

- 브라우저에 있는 PDF에 검수 결과 주석만 붙인 **새 파일** 저장.
- 글자·원본 파일은 수정하지 않는다. 기존 주석은 **덧붙인다**. 인디야 주석에 작성자 표식.

### 시험 (버튼 전)

대표 PDF 서너 개. 포함: `/Rotate` 페이지, CropBox ≠ MediaBox.

**합격 기준**

- 아크로뱃·맥 미리보기·크롬에서 주석이 해당 말 위에 걸친다.
- 아크로뱃 주석 목록에 `할때 → 할 때`가 UTF-16BE로 한글로 읽힌다.

**시험 체크**

- 좌표: 결과 데이터 + 글자 조각 → `convertToPdfPoint`. DOM 박스를 긁지 않음. 주석을 pdf.js로 다시 읽어 수치 비교.
- QuadPoints: 스펙 순서 vs 아크로뱃 순서 비교. `/Rect`가 점을 감쌈. 줄바꿈이면 사각형 복수.
- AP(외형) 있음/없음 비교 — **기본은 AP 넣기**.
- 한글 `/Contents`·`/T`: BOM 있는 UTF-16BE (`pdf-lib`면 `PDFHexString.fromText`).
- 암호: 열기 암호 / 주석 금지 파일 안내 분리. 제한을 풀지 않음.
- 최대 용량 파일로 시간·메모리 측정.

**라이브러리:** 시험·제품 모두 `pdf-lib`(MIT). 주석 사전은 직접 구성.

### 제품 UI (시험 통과 후)

- 주 받기: 주석 PDF.
- 엑셀: 「목록으로 받기」 등으로 유지.

## 3. 단계 ② — 원고 TXT 1차

### 목적

편집자·외부용 원고 TXT. 인디야 검사 입력 개선은 부수·나중.

### 층

1. **공짜 신호** — 태그 PDF면 `getMarkInfo` / `getStructTree`, Artifact, `hasEOL` 먼저. 없으면 위치 기반.
2. **글자 정리** — 낱자·NFD→NFC·깨진 글자. 불가 구간은 “추출 불가”.
3. **상자** — 위치·크기로 블록.
4. **역할** — 본문·제목·머리말·쪽수·캡션 등. 규칙 + 사람 UI. (형태소 AI는 이 단계에 넣지 않음.)
5. **순서** — 본문·제목만, 위→아래(다단 규칙).
6. **문단** — 들여쓰기·단 폭·종결부호·따옴표. 빈 줄만 믿지 않음. **쪽·단 이음** 후보 규칙 + 확신 낮으면 화면 확인.
7. **줄 끝 공백** — 애매하면 붙/띄 강제하지 않고 **「줄바꿈 확인」**.
8. **검수** — 확신 못한 블록만 화면에 모음.

### TXT 받기 방식

- **화면에서 확인을 마친 뒤에만** 깨끗한 TXT를 받는다. (표식 넣은 TXT / 병행 목록 방식은 채택하지 않음.)
- 「자동 생성·검수 전」은 **본문 첫 줄이 아니라 파일명** (`…_검수전.txt`). 확인 후에는 `_검수전` 제거.
- 검수용 화면·중간본에는 쪽 경계를 남겨 PDF 대조. **최종 TXT**에서는 쪽 경계 표시 제거.
- 저장: UTF-8, Windows 기본은 BOM+CRLF. 실제 쓸 메모장·한글·워드에서 확인.

### 1차 합격 기준 (샘플 정답 TXT와 비교, 시험 전 숫자 확정)

- 남은 머리말·쪽수: 0
- 문단 수: 정답과 같거나 ±1
- 「줄바꿈 확인」비율: 본문 줄의 일정 비율 이하

### 하지 않는 것 (2·3차로 미룸)

캡션·각주·미주·사이드바까지 “완성 원고”로 복원하는 일. AI로 좌표·블록을 나누는 일.

## 4. 단계 ④ — 인디자인 반영 (나중)

검토용 엑셀과 디자이너용 표를 **나눈다**.

| 넘기는 것 | 내용 |
|-----------|------|
| `replace.tsv` | UTF-8, `찾을 말` / `바꿀 말`만. 확정 쌍만. |
| 스크립트 하나 | 검사마다 새로 만들지 않음. |
| 안내 한 장 | 미리보기 → 적용 |

**표 작성 시**

- `변형>교정` 한 줄씩 펼침, `^` → 공백.
- excepts·문맥 의존 항목 제외.

**스크립트**

- 앞·뒤 모두 「한글이 아닐 때」만 치환. 활용형은 표에 있을 때만.
- 표에서 `찾을 말` 중복·연쇄 변환이면 중단. 길이순은 안전장치.
- 미리보기 로그(페이지·원문·교체·0건 쌍) 후 적용. `UndoModes.ENTIRE_SCRIPT`.
- UTF-8 읽기, BOM 제거. 바꿀 말 `$` `~` `\` 처리.

PDF 글자 수정·브라우저→인디자인 직접 연동은 하지 않는다.
