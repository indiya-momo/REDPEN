# 원고 팝아웃 창 설계 (2026-07-31)

**상태:** 보류 — 오픈베타 종료 후 착수  
**범위:** 문서화만. 베타 기간 중 구현하지 않음.

## 1. 배경·목표

현재 메인 화면은 한 탭 안에서 왼쪽 검수 패널과 오른쪽 원고(PDF)를 분할하며, 세로 핸들로 너비만 조절한다.

목표: **원고만 새 브라우저 창으로 분리(팝아웃)** 해 듀얼 모니터 등에서 검수·원고 위치를 자유롭게 두고, 클릭·페이지 이동은 지금과 같이 맞물리게 한다.

비목표(이번 기획에서 제외):

- Electron 등 네이티브 멀티 윈도우 앱
- 같은 URL을 탭 두 개로만 복제하는 방식(양방향 동기화가 사실상 불가)
- 검수 패널만 팝아웃

## 2. 합의된 UX

| 항목 | 결정 |
|------|------|
| 분리 대상 | 원고(PDF)만 |
| 창 위치 | OS/브라우저가 자유 (좌·우 모니터 가능) |
| 원래 탭 | 오른쪽 원고 자리를 비우고 **검수 패널만 전체 폭** |
| 복귀 | 「합치기」 또는 팝아웃 창 닫기 → 좌·우 분할 복원 |
| 최종 동기화 목표 | **양방향** (검수 ↔ 원고) |

진입점(버튼 위치: 원고 헤더 vs 미리보기 바 등)은 착수 시 UI에서 확정.

## 3. 왜 팝아웃 + BroadcastChannel인가

- **탭 복제:** 탭마다 독립 컨텍스트라 선택·페이지를 맞추기 어렵다.
- **팝아웃 + 채널:** 같은 origin에서 세션(IndexedDB·auth)을 공유하고, 가벼운 이벤트만 주고받으면 된다.

## 4. 기술 요지

### 4.1 PDF·세션

- PDF 바이너리를 채널로 보내지 **않는다**.
- 팝아웃도 같은 origin → **IndexedDB 세션에서 직접** 원고를 읽는다.
- 채널에는 `currentPage`, 선택된 결과 ID 등 **가벼운 상태**만 전달.

### 4.2 인증

- 같은 origin이면 firebaseAuth 세션이 유지될 가능성이 높다.
- 착수 시 팝아웃에서 `subscribeAuthSession` 정상 여부를 **반드시 확인**.
- 실패 시: 원 탭으로 돌아가라는 안내로 1차 대응 가능.

### 4.3 BroadcastChannel 스코프

- 채널 이름에 **projectId / sessionId** 등을 넣어 스코프한다.
- 스코프 없으면 같은 브라우저의 다른 프로젝트 탭과 페이지·선택이 간섭한다.

### 4.4 window.open

- **사용자 클릭 핸들러 안에서 동기적으로** `window.open` (팝업 차단 회피).

### 4.5 창 닫힘·합치기

- `beforeunload` / `visibilitychange`만으로는 비정상 종료에 부족할 수 있다.
- 원 탭이 팝아웃 **heartbeat**를 보다가 끊기면 자동으로 합쳐진(분할) 상태로 되돌리는 방안을 권장.

## 5. 단계적 범위

### 1차 (쓸 수 있는 팝아웃) — 예상 약 1주

포함:

- 원고 팝아웃 / 합치기
- 원래 탭: 검수 전체 폭
- IndexedDB 로드 + 스코프된 BroadcastChannel
- **검수 → 원고:** 결과 클릭 → 페이지 이동 (기존 동작을 팝아웃으로 확장)
- **원고 → 검수:** **페이지 번호 정도의 최소 역방향**
- heartbeat / 비정상 종료 시 원 탭 복귀

제외(2차로 미룸):

- 하이라이트·목록 선택 양방향 동기화
- 창 위치 기억, 새로고침 후 팝아웃 복구
- 다중 팝아웃

### 2차 (완성도) — 1차 이후 추가 약 3~7일, 합산 약 1.5~3주

- 하이라이트/선택 양방향
- 창 위치·새로고침 복구 다듬기
- 인증·예외 UX 보강

## 6. 베타·freeze와의 관계

- `ruleEngine` / 맞춤법 매칭 / MainScreen dead props 제거 등과 **충돌하지 않는 부가 기능**으로 본다.
- 오픈베타 중에는 **구현하지 않고 이 문서만 유지**.
- 착수 전: freeze 목록·당시 레이아웃 코드를 다시 확인.

## 7. 왜 일정이 길다고 보았는가 (요약)

한 탭 안에서는 검수↔원고가 같은 메모리라 호출 한 번이면 된다.  
창을 나누면 상태 동기화, 이중 로드, 레이아웃 모드 전환, 브라우저 팝업/종료 예외, 교정 제품 신뢰도까지 비용이 붙는다.  
그래서 「새 창 하나」가 아니라 **통신·복구 규칙이 있는 작은 기능**으로 일정을 잡았다.

## 8. 착수 체크리스트 (베타 종료 후)

1. 버튼 위치·카피 확정  
2. 세션 키 / 채널 이름 스코프 스키마 확정  
3. 팝아웃 라우트 또는 쿼리(`?popout=manuscript`) 방식 선택  
4. 1차: 단방향 페이지 점프 + 페이지 번호 역방향 + 합치기/heartbeat  
5. auth 팝아웃 스모크  
6. 2차: 하이라이트·선택 동기화  

## 9. 대화에서 확정한 Q&A

- 원고만 팝아웃해도 좌우 위치 변경 가능? → **가능** (일반 창 드래그)  
- 검수 클릭 시 원고 따라가기? → **필수**  
- 원고 조작 시 검수도? → **최종 목표 양방향**, 1차는 페이지 번호 최소  
- 팝아웃 후 원래 탭 오른쪽? → **비우고 검수만 확장**
