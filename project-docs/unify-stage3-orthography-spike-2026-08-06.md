# 표기 통일 목표 3단 — 철자·음차 이형태 스파이크

**상태:** 스파이크 — PDF `pageTexts`로 일관성 탭에 자동 표시 · 확정/Discover 본선 미연결  
**날짜:** 2026-08-06  
**관련:** `unify-phase2-pattern-2026-07-31.md` §0 · `unify-candidate-spacing-redesign-2026-07-29.md` §0

## 한 줄

국립국어원 API·맞춤법 시트 없이, **원고 안**에서 철자 이형태 후보를 잡되, 문제는 **(1) 후보 식별**과 **(2) 이형태 클러스터링**으로 나눈다.

## 원칙 (1·2단과 맞춤)

| 항목 | 결정 |
|------|------|
| 대상 | **명사만** + 라틴 **4자 이상** 병기. 용언·`…다`·조사 잔여·`…하` 미완성 제외 |
| 근접 이웃 | 음절 수 동일·초성 동일·자모 거리 ≤1·이웃 최대 2 · 변형 5개 이상 클러스터는 mix 제외 |
| 기본 추천 | **문서 다수형** (`recommendedUnify`) |
| 규범(`replace`/시트) | 배지·힌트만 (스파이크에서는 미연결) |
| 확정 | `needsVerification: true` — 자동 승격 금지 |
| 결과 셰이프 | 기존 Discover 클러스터와 유사 (`variants` / `counts` / `recommendedUnify`) |
| 성장 경로 | 이후 `consistencyDecisions` 확정 쌍 → 시드 누적 (한 줄만 예약) |
| 시트 부스터 | 외래어 C/C1/C2 `find`∪`finds`는 **선택 부스터**. `finds≥2`만으로는 고유명 음차·`도널드`/`도날드`(단일쌍) 커버가 부족함 |

## 스파이크 순서

1. **(1)-a 라틴 괄호 병기 앵커** — `한글{2,}\s*\([A-Za-z]…)`  
   - 같은 `latinKey`에 한글이 둘 이상 → 고신뢰 혼용  
   - 앵커 한글과 **자모 편집거리 ≤ 2**(같은 첫 음절·길이 ±1) 이웃 → 보조 혼용  
2. 확실한 쌍에서 **음절 차**(`널↔날` 등)를 모아 (2)-c 정규화 규칙 초안 재료로 씀  
3. (2)-a 전역 자모 거리·(1)-b 음절 이상치·(1)-c UNKNOWN 수확은 **후속**  
4. Discover UI 연결은 스파이크 검증 후

## 실행

**앱(권장):** PDF 업로드 → 일관성 탭 「표기 통일 추천」— 추출이 끝나면 **철자·음차 이형태 (스파이크)** 블록이 `pageTexts`로 자동 스캔됩니다. 검수권 없음.

**CLI(옵션):**

```bash
npm run spike:unify-ortho-anchors
npm run spike:unify-ortho-anchors -- path\to\text.txt
```

## 나중에 쓸 수 있음 (예약)

**AI로 “비슷한 상황인데 이름만 살짝 다른” 이형태 걸러내기.**

- **동기:** 현재 스파이크 자모 규칙(음절 수 동일·초성 동일·중성 혼동만)은 `도널드`/`도날드`에는 맞지만, `시몬`/`사이몬`(음절 삽입)·`로사`/`로자`(초성 ㅅ↔ㅈ) 같은 **고유명 음차 갈림**은 의도적으로 못 잡음. 규칙을 넓히면 `자식`/`지식`류 오탐이 바로 늘어남.
- **가설:** 이런 쌍은 AI가 “같은 인물·같은 외래 고유명의 철자 이형태인지”를 보는 편이 나을 수 있다. (조사·용언 검토와 같이 **규칙으로 후보를 좁히고 AI로 걸러/묶기**가 자연스러움.)
- **역할 후보 (미결정):**
  1. **발견** — 문서 안 이름·외래 명사에서 이형태 쌍을 직접 찾기  
  2. **검토** — 규칙/병기 후보만 “같은 이름 이형태인지” 걸러내기  
  3. **둘 다** — 발견은 느슨하게, 표시 전에 AI로 걸러 목록에만 올리기  
- **상태:** 스파이크·제품 경로 **미구현**. 나중에 3단 확장 시 이 절을 출발점으로 재검토.
