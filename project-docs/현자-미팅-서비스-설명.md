## 1. 서비스가 뭔지 (한 줄)

> **AI가 글을 고쳐 주는 앱이 아니라**, 인디자인 등에서 만든 **조판 PDF**에서 **맞춤법·표기 일관성**을 **규칙으로 자동 탐지**하고, **PDF 위에 위치를 표시**하는 **브라우저 로컬** 도구입니다.

**포지셔닝:** 맞춤법 앱 대체 X → **「PDF 교열·교정 전처리 스캐너」**

| 원칙 | 내용 |
|------|------|
| 자동 수정 | ❌ |
| 자동 탐지 + 하이라이트 | ⭕ |
| 원고·PDF 서버 업로드 | ❌ (검수 본문은 브라우저 안에서만) |
| AI 문장 추천·문맥 교정 | ❌ (MVP 비목표) |

**브랜드:** 대외 이름 **「인디야: 교정냥 모모의 여행」** · 저장소/배포명 **REDPEN**

## 3. 현재 되는 기능 (2026-08 기준)

### 사용자 흐름

1. **대문(웰컴)** → 검수 시작  
2. **PDF 열기** (파일 선택 / 드래그 / 「PDF 열기」로 재연결)  
3. **맞춤법 확인** 또는 **일관성 확인** 탭  
4. 적용할 **규칙 ON/OFF** · (일관성) **표기 통일 추천** 찾기  
5. **검수 실행** → 좌측 **결과 목록** + 우측 **PDF 하이라이트**  
6. 항목 클릭 → **해당 페이지·위치**로 이동  
7. **피드백 보내기** (Google Form 또는 클립보드)

### 맞춤법·주의

- **내장 맞춤법 규칙** (시트 `spelling_rules` → JSON 동기화)  
- **주의(편집자 검토) 규칙** — find/replace·팁·켜기/끄기  
- **본보조(보조용언) 규칙** — 별도 시트, 할당량·검사에서 제외 등 정책 적용  
- 조판 PDF **줄바꿈·공백**을 고려한 **유연 매칭** (find → regex)  
- 규칙별 결과 묶음 · 진행률 표시 · 검사 중 버튼 비활성  

### 일관성 · 표기 통일 추천 (핵심 확장)

규칙 기반 「일관성 찾기」와 별도로, 문서 안 **띄어쓰기만 다른 이형태**를 모아 통일 방향을 고르게 하는 **표기 통일 추천**이 동작한다.

#### 제품 목표 단계 (숫자 = UX 1차/2차와 혼동 금지)

| 목표 단계 | 내용 | 예 | 상태 |
|-----------|------|----|------|
| **1. 띄어쓰기 기반** | 붙임/띄움만 다른 표기를 묶어 통일 제안 | `금융위기` ↔ `금융 위기` | **운용 중** |
| **2. 요소(편측) 확장** | 1에서 고른 정책을 접두·접미 계열로 확장 | `경제○○` 붙임 → 같은 접두 제안 | **운용 중** (2차 pattern) |
| **3. 철자·표기 이형태** | 띄어쓰기와 무관한 철자·음차 혼용 | `도널드` ↔ `도날드` | **스파이크·DEV만** (프로덕션 미연결) |

#### 사용자 플로우 (1차 → 2차)

1. **찾기** → 계열·단일·용언 등으로 묶인 이형태 목록  
2. **1차** — 붙여쓰기/띄어쓰기 선택. **80% 이상 표기 형태는 soft 자동 선택**(미터치 = 확정과 동일 시드로 2차에 반영)  
3. 1차 목록을 채우면 → 「2차 표기 통일을 진행합니다」  
4. **2차-A (`pattern_pick`)** — 접두/접미 패턴 후보 + 건수·Explain(발견 횟수·계열 수·점수·예) · 체크 · PDF Preview가 선택에 따라 갱신 → **다음**  
5. **2차-B (`secondary_pairs`)** — 1차와 같은 카드 UI로 확장 이형태 선택 · 미선택 = 예외  
6. 완료 후 1차로 복귀 · 조건형 요약 유지  

#### 품질·잡음 억제 (요약)

- Discover 후 **어간/조사·용언·위성·Kiwi phase2** 등으로 목록을 정규화  
- **용언 추정·보조용언 검토** 배지 항목은 기본 PDF 체크·발견 집계에서 **제외(검토 유예)**  
- 잡음 어절(예: `순간`, `오래`, `어느`, `각종`, `벗어난` 등) · 패턴 시드에서 **검토 중 클러스터·블랙리스트 head** 제외  
- 패턴 후보는 **증거 하한**(계열 수·발생 횟수) + score/Explain  

#### 엔지니어링 메모 (현자용)

- 목록 조립은 `unifyFindListPipeline`으로 **찾기 실행 ↔ 목록 재조합** 경로를 맞춤  
- 아코디언은 `listEpoch`+`unifyPhase`로 remount (검색=펼침 초기화)  
- **3단 오표기**는 `OrthoSpikeDevPanel` — **DEV 전용**  
- 베타 freeze: **`ruleEngine`·spelling/caution 매칭 코어**는 손대지 않음. **표기통일 오케스트레이션(`unifyCandidate*` 등)은 freeze 밖**으로 합의  

### PDF·안정성

- **PDF.js**로 텍스트 추출 · **TextLayer** 기반 하이라이트  
- **한글 cMap** · **재저장 PDF** 안내 (차단 대신 advisory)  
- **50MB 초과** → 검수 실행 불가 + **PDF 나누기** 외부 링크 (iLovePDF)  
- **스캔 PDF** → 명확 거절 메시지  
- **IndexedDB** 세션 복원 시도 (브라우저·권한에 따라 실패 가능)  
- **인쇄면 표시** 설정 (스프레드 등)  

### UI·부가

- **대문 PC / 모바일** 분리 (`welcome-pc` / `welcome-mo`)  
- **모모의 방** (비밀 공간, 방명록 등)  
- **버전 뱃지** (SemVer + 빌드 ID)  
- **PostHog** 익명 통계 (opt-out 가능) · **피드백** 모달  

### 개발·품질 (운영자 관점)

- **테스트 ~1870+** · husky pre-commit/pre-push  
- **GitHub Pages** 자동 배포 (`main` push → `docs/`)  
- 규칙 JSON **스키마 검증** 스크립트  

### 아직 UI에 없거나 “준비 중”인 것 (중요)

| 항목 | 실제 |
|------|------|
| 「기준 저장 준비 중」 문구 | **규칙 세트 이름·여러 세트·저장 버튼 UI** 미노출 (로직은 있음) |
| 규칙 세트 CRUD | 코드·localStorage는 있으나 **검수 화면에서 숨김** |
| **목차 검사** | UI·카피 **플레이스홀더** 수준 (본격 검사 미완) |
| 슬롯·1000개 한도 | 코드에 남아 있으나 **베타 UI에서는 슬롯 개념 비노출** |
| 표기 통일 **3단**(철자 이형태) | DEV 스파이크만 · 시몬/사이몬·로사/로자 등 **음절·초성 한계** 문서화 |
| 로그인·협업·클라우드 원고 | 없음 |

- 서버에 **원고·검사 결과** 저장  
- 「앞 100페이지만 검사」(사용자 혼란으로 **채택 안 함**)

## 5. 개발자(현자)에게 꼭 물어볼 점

### 베타 go / no-go

1. **지금 상태로 비공개 베타에 나가도 되는 최소 조건**은 무엇인가? (smoke 항목 5개 정도로 줄여 달라)  
2. **freeze 기간**에 **절대 손대지 말아야 할 영역** (ruleEngine, session, PDF gate 등) 확인.  
   - **갱신(2026-08):** 표기통일 `unifyCandidate*`·패널 오케스트레이션은 **freeze 밖**으로 진행 중. `ruleEngine`/spelling·caution 매칭은 계속 freeze.  
3. **hotfix만 허용**할 때, 어떤 변경은 hotfix가 아니라 **다음 마일스톤**인가?

### 제품·문서

4. **PRD/와이어프레임 없이** 키운 프로젝트인데, **지금 시점에 고정해야 할 문서**는 무엇인가? (1페이지 Concept + Known Issues면 충분한지)  
5. 테스터에게 **「하는 일 / 하지 않는 일」** 외에 **반드시 읽게 할 문단** 3줄은?  
6. **50MB·300p** 운영 한도 — 베타에서 유지 vs 완화, **데이터 없을 때** 기본값 조언.

### 기술·구조 (1인 + AI 개발)

7. **PC / 모바일 코드 분리 + git worktree** 로 역할 나눈 구조 — 장기적으로 괜찮은지, merge 전략.  
8. **규칙 autosave는 되는데 UI는 「준비 중」** — 베타에서 **오해를 막는 카피** 한 줄 추천.  
9. **IndexedDB 세션 복원 실패** — 베타 Known Issue로 두기 vs 반드시 고치기.  
10. **PostHog 6종 이벤트** — 베타에 필요한 최소인지, 과한지.

### 운영·법·신뢰

11. **피드백 Form**에 원고 PDF 첨부 금지 — 안내 문구·NDA 관점에서 충분한지.  
12. **통계 opt-out** 문구 — 베타에서 **법적·신뢰** 측면 보완할 것.  
13. 초대형 베타 **몇 명·어떤 시나리오**로 시작하는 게 좋은지 (편집자 2~3명 등).

### 로드맵 판단

14. **목차 검사·규칙 세트 UI·Worker·표기통일 3단** 중 **베타 후 첫 1개**로 뭘 추천하는지.  
15. **인앱 PDF 나누기** vs **외부 링크** — 1인 프로젝트에서 언제 in-app을 검토할지.

## 7. 미팅 시 한 장 요약 (구두용)

- **뭐:** 조판 PDF **탐지 + 위치 표시**, 로컬, AI 교정 아님  
- **누구:** 편집·교정 현장, PDF 유출 싫은 사람  
- **지금:** 맞춤법·일관성 + **표기 통일 추천(1차 띄어쓰기 → 2차-A 패턴 선택 → 2차-B 확장)** 운용 · 3단은 DEV만 · 베타 준비  
- **안 함:** OCR/스캔 PDF(Tesseract 포함 재확인)·원고 서버 저장·자동 수정  
- **다음:** 베타 freeze(`ruleEngine`) → 피드백 → 성능/목차/규칙 UI / (이후) 표기통일 3단  
- **물어볼 것:** **go/no-go**, **freeze 범위**, **문서 최소선**, **한도·세션·오해 문구**
