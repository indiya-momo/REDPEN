# 엑셀 → 교체주석을 위한 내보내기 형식

**작성:** 2026-11-20  
**상태:** 열 구성 합의 · **내보내기 형식만 1차** · 올리기는 인디자인 Replace 스모크 이후  
**상위:** 검수 결과 엑셀(`exportResults.js`) · 인디자인 Replace · 원고 작업대 `ManualFinding`

---

## 0. 한 줄 원칙

엑셀은 **사람이 수정안을 다는 표**이자, 나중에 **같은 PDF가 열린 인디야에서 한 행을 `ManualFinding`으로 넣는 입력**이다. 주석 파이프를 새로 만들지 않는다.

---

## 1. 합의된 전제

| 항목 | 결정 |
|------|------|
| 누가 | 편집자가 수정안을 달고, **같은 PDF가 열린 인디야**에서 올린다. 디자이너가 엑셀을 올리지 않는다. |
| 디자이너에게 | 결과 **주석 PDF**. 엑셀은 회의·보관용으로도 쓸 수 있다. |
| 1차 범위 | **내려받기 형식만** 바꾼다. 올리기 UI·파서는 스모크 이후. |
| 시트 | **워크시트 하나.** 수정안을 두 시트에 두지 않는다. 상단 안내·요약 줄은 유지. |
| 데이터 행 | **한 행 = 한 발견.** 구분·묶음·기준·설명 **병합 없음.** |
| 숨김 열 | 쓰지 않는다. 기계용 열은 보이게, 헤더에 `※수정하지 마세요`. |
| 연결 | `페이지` 라벨(`34P`, `1/2`)은 **읽기 전용.** 위치는 `행ID` + `pageNum` + `start` + `end`만. |
| 쪽 | 사람용 `페이지`는 인쇄 쪽 라벨. 기계용은 PDF **`pageNum`**. |
| 오프셋 | 원고 작업대와 같음. `page.text`의 `[start, end)`. |
| 수정안 | 맞춤법 규칙은 채움. 검토·표기 통일(📌 없음)은 **빈 칸.** 📌통일형만 채움. 빈 칸은 나중에 고침 없음으로 제외. |
| 올리기(나중) | 행 → `ManualFinding` → 같은 거부 규칙(빈 고침, 원문과 같음, 줄바꿈, `matchedText === page.text.slice(start,end)`). |
| 원고 조각 | 브라우저에서만 읽음. Firestore·PostHog에 본문 안 보냄. |
| 엑셀 수식 | `발견 문구`·`수정안` 등은 **문자열 셀.** `=` `+` `-` `@`로 시작해도 수식으로 열리지 않게. |

비범위(1차): 올리기 버튼, 다른 PDF에 씌우기, 엑셀만으로 주석 만들기, `ruleEngine` 변경.

---

## 2. 열 순서

3행이 헤더. 4행부터 데이터. 1행 안내, 2행 요약은 지금처럼 가로로 합침(데이터 행은 합치지 않음).

### 사람용 (왼쪽)

| 열 | 맞춤법 | 표기 통일 | 누가 고치나 |
|----|--------|-----------|-------------|
| 구분 | 있음 | 있음 | 읽기 |
| 묶음 | 있음 | 없음 | 읽기 |
| 기준 | 있음 | 있음 | 읽기 |
| 설명 | 있음 | 있음 | 읽기 |
| 발견 문구 | 있음 | 있음 | 읽기(검증 복사본. 위치를 이 칸으로 찾지 않음) |
| 수정안 | 있음 | 있음(대부분 빈 칸) | **여기만 편집** |
| 페이지 | 인쇄 쪽 라벨 | 같음 | 읽기. `1/2` 해석 안 함 |

### 기계용 (오른쪽, 헤더 `※수정하지 마세요`)

| 열 | 값 |
|----|-----|
| 행ID | 재내려받아도 같은 발견이면 같음. `pageNum`+`start`+`end`+출처(카테고리·기준)로 만듦. `1/2` 금지. |
| pageNum | PDF 쪽 (1부터) |
| start | `page.text` 시작 (반열린) |
| end | `page.text` 끝 |
| pdfName | 올린 PDF 파일명 |
| pdfPages | 그 PDF 쪽 수 |
| pageFp | 그 쪽 `page.text` 지문(짧은 해시). 다른 PDF·다시 만든 PDF면 나중에 행 제외 |

`start`는 인스턴스 `index`와 같다. `end = index + matchedText.length`. 하이라이트·주석과 같은 구간.

---

## 3. 행을 넣는 규칙

- 화면에서 **숨긴** 발견은 행을 넣지 않는다.
- 수정 추가(`manual`) 행도 같은 시트에 넣는다. 수정안은 사용자가 적은 고침.
- 검색만(`manuscript-search`)은 고침이 없으면 넣지 않는다.
- 옛 허브 스냅숏을 다시 받을 때는, 위치 열이 없으면 사람용만 채우고 기계용은 비운다. 그런 파일은 나중에 올리기 대상이 아니다.

---

## 4. 나중에 올리기 (구현하지 않음, 형식만 맞춤)

1. 지금 연 PDF의 `pdfName`·`pdfPages`가 파일과 다르면 **경고 후 중단 또는 전부 제외**(구현 때 한 가지로 고정).
2. 각 행: `page.text.slice(start,end) === 발견 문구` 아니면 제외.
3. 수정안이 비었거나 발견과 같거나 줄바꿈이면 지금 `manualAddRejectReason`과 같게 제외.
4. 통과 행만 `addManualFinding`. 목록·빨간 레이어·인디자인 Replace는 기존 경로.

엑셀 안내 문구에 「수정안만 고치세요. 오른쪽 회색 열은 수정하지 마세요.」를 넣는다.

---

## 5. 끝난 판정 (1차 내보내기)

- 내려받은 시트에서 데이터 행이 병합되어 있지 않다.
- 한 발견이 한 행이고, `pageNum`·`start`·`end`·`행ID`가 보인다.
- 표기 통일 📌만 수정안이 채워지고, 나머지는 빈 칸이다.
- `발견 문구`가 `=`로 시작해도 엑셀이 수식으로 열지 않는다.
- 올리기 버튼은 **아직 없다.**
