## 1. 전제 스모크 (구현 게이트)

구현·제품 UI 착수는 아래가 **통과한 뒤**만 한다. 이 문서는 그 전에도 **계획·합의용**으로만 둔다.

| # | 전제 | 판정 |
|---|------|------|
| S1 | **전체 쪽을 유지**한 PDF에 인디야 Replace를 넣고, 인디자인 Import→Accept→**본문↔고침 일치** | 필수 |
| S2 | (가능하면) ID 내보내기 원본. ezPDF 재저장본은 보장 밖·결과만 기록 | 출처 명시 |
| S3 | Acrobat Replace vs 인디야 합성 — 원인 분리용 (형식은 Contents 스모크 통과) | 권장 |

S1 실패 시 이 분할 설계의 전제가 성립하지 않는다 → 구현하지 않고 원인 먼저.

## 2. 목표 · 비범위

### 목표

`indesignReplace` 내려받기에서, finding이 많을 때 **같은 원본 쪽 구조를 유지한 PDF 여러 개**(± ZIP)로 나눠, 묶음마다 해당 범위 주석만 담는다.

### 비범위 (이 초안)

- 쪽을 **잘라 낸**(페이지 subset) PDF를 제품 기본 경로로 쓰기  
- 분할로 QuadPoints·Tw·Accept 정확도 향상 주장  
- 서버에 원고·PDF 저장  
- Insert 전용 경로

## 3. 고정 방향 (합의)

| 항목 | 결정 |
|------|------|
| 기본 분할 | **전체 쪽 유지** + **주석만** 쪽 범위(또는 합의된 건수 규칙)로 나눔 |
| 쪽 자른 PDF | **실험 항목만**. 제품 기본 아님. Import 위치·“not from InDesign” 위험 |
| 효과의 성격 | 시험 결과에 **종속**. 아래 §4 |
| 쪽 범위 | 묶음 간 **비겹침** |
| 정확도 | 구간 자체 점검·일괄 Accept 스모크는 **분할과 별도로** 유지 |

---

## 4. 운용 순서와 효과 (시험 종속)

두 효과가 **한 순서에서 동시에** 보장되지 않을 수 있다.

| 운용 | 중간 확인(오버셋·쪽수) | 매핑 위험(Accept가 문서 수정) |
|------|------------------------|-------------------------------|
| A. 한 묶음 Accept → 확인 → 다음 Import | 생김 | **큼** |
| B. 묶음 PDF를 **한꺼번에 Import** → 패널에서 순서 Accept | 습관에 의존 | 상대적으로 작을 **수** 있음 |

- Adobe 도움말: 검토용 PDF 이후 인디자인 문서를 수정하면 매핑이 어긋날 수 있음.  
- 여러 PDF 주석을 한 문서에 가져오는 것은 도움말상 **지원되는 경로**로 보임 → B가 성립할 여지.  
- **제품 안내·기본 권장 순서는 A/B 스모크 후**에만 고정한다. 스펙에 “효과가 시험 결과에 달려 있다”를 조건으로 둔다.

### 시험에 넣을 항목 (분할 검증)

1. 전체 쪽 유지 + **일부 주석만** 담은 PDF → Import·Accept·위치·본문  
2. (실험) 쪽을 잘라 낸 PDF → 같은 ID 문서에 Import되는지·위치가 맞는지  
3. 순서: **전부 Import 후 Accept** vs **Accept 후 다음 Import** 차이 기록

## 5. 묶음 경계 · 겹침

### 소속 규칙 (초안)

- finding의 **시작 쪽 `pageNum`**이 속한 묶음에만 넣는다.  
- 줄바꿈·쪽 넘김으로 여러 쪽에 걸친 구간도 **쪼개지 않고** 시작 쪽 묶음에 둔다.

### 겹침

- `prepareIndesignReplaceFindings`의 **긴 구간 우선**은 **전체 finding에 먼저** 적용한 뒤, 통과분만 묶음에 배분한다.  
- 묶음마다 겹침을 다시 돌리지 않는다 (경계를 넘어 일관).

### 테스트 (구현 시)

- 쪽 넘김 1건 → 시작 쪽 묶음에만  
- 경계 인접 겹침 1건 → 전역 긴 구간 우선 후 한 묶음에만

---

## 6. 산출물 · ZIP · 성능

- 생성 위치: **브라우저 로컬** (ZIP 포함). 서버 업로드·보관 없음.  
- 각 묶음 파일명 예: `{base}_인디자인용_p{from}-{to}.pdf` 또는 건수 기준 접미사.  
- 측정(구현 전·스파이크): 쪽 수 × 묶음 수에 따른 **재저장 시간·메모리·ZIP 크기**. 750쪽대 감당 여부.  
- 묶음 크기(쪽 수 vs 주석 건수 vs 장)는 **현장(모모집사·디자이너)과 합의**. 구현은 “페이지 구간 → 그 구간 finding만”이면 충분.
