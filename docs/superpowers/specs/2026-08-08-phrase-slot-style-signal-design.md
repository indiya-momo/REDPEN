# 공통 항목 — 접미 계열 붙임/띄움 스타일 신호 (1차)

Date: 2026-08-08  
Status: implemented (1차 배지·카운트)  
Priority: 표기통일 파이프라인 통합과 별도 (완료분)

## 문제 · 질문 구분

편집자가 보고 싶은 질문이 두 가지다. 섞으면 안 된다.

| 질문 | 기능 | 예 |
|------|------|-----|
| *이거랑 이거, 같은 단어를 다르게 썼나?* | **표기 통일 추천** | `대출프로그램` = `대출 프로그램` (앞말 동일 쌍) |
| *이 문서에서 `~서비스` 계열이 붙임/띄움 스타일이 혼재한가?* | **공통 항목 스타일 신호** | `사회 서비스` / `생활서비스`는 **다른 단어**지만 접미 스타일 참고 |

표기통일 페어링(B안)에 접미 혼재를 넣지 않는다. 서로 다른 단어를 “통일하라”고 잘못 추천하는 사고가 난다.

## 1차 범위 (합의)

- **배지 · 카운트 표시만**
- 필터 · 정렬 · “혼재만 보기” · 표기통일로의 브릿지/승격 → **미룸** (베타에서 배지 유용성 확인 후)
- 표기통일 discover / 1·2차 파이프라인 **코드 경로 불변**

### 1차를 배지만으로 좁히는 이유

1. 검증 우선: 신호가 편집자에게 유용한지 먼저 확인. 필터는 UI 표면만 키운다.
2. `@` / `@˅` 슬롯이 항상 쌍으로 등록된다는 보장 없음. 필터까지 얹으면 “혼재인데 필터 안 걸림” 버그 면이 넓어짐. 배지만이면 최악도 “카운트가 안 보임” 수준.
3. 작업 범위: 파이프라인 통합 뒤 **별도 작은 UX**로 유지. 중간 크기 리팩터로 키우지 않음.

## 표시 · 배지 위치 (확정)

현재 결과 UI는 `@서비스` / `@˅서비스`가 **별도 결과 카드**(각자 헤더)다. stem 신호는 슬롯 단위가 아니라 **stem 단위**이므로:

**확정: stem 요약 행을 해당 stem의 슬롯 카드들 바로 위에 1회만 삽입한다.**

- `@서비스` 헤더 · `@˅서비스` 헤더 **각각에 배지를 중복 부착하지 않는다.**
- 1차에서 슬롯 카드를 stem 아코디언으로 **재그룹·중첩하지 않는다.** (기존 카드·체크·페이지 칩 동작 유지)
- 요약 행은 참고용(비조작). 클릭해도 표기통일·필터로 연결하지 않는다.

예:

```text
공통 항목 찾기
  서비스 · 붙임 N · 띄움 M · [스타일 혼재?]     ← stem 요약 행 (1회)
  [@서비스 카드 …]
  [@˅서비스 카드 …]
```

표시 문자열:

```text
붙임 N · 띄움 M
```

`혼재 === true`일 때만 같은 행에 **스타일 혼재** 라벨 추가.  
(통일 후보 아님 · 참고 정보.)

기존 hit 목록(채움별 행 · 페이지 칩)은 그대로.

## 카운트 정의 (확정)

**N / M = 어절 occurrence(MatchInstance) 개수** — 페이지 수가 아님.

근거: 공통 항목 UI·`groupPhraseSlotInstancesByFill`의 `count`가 이미 `instances.length`(occurrence)다. 노란 배지(예: 프로그램 21)와 같은 단위로 통일한다. 이후 필터를 붙여도 재정의하지 않는다.

- 붙임 N = 해당 stem의 **붙임 슬롯** 규칙 hit occurrence 합
- 띄움 M = 해당 stem의 **띄움 슬롯** 규칙 hit occurrence 합

## Stem 키 (확정)

등록 패턴 `tailWord`에서 슬롯 마커(`@` 등)·공백·˅(`SPACE_VISIBLE_CHAR`)를 제거한 **접미 문자열**.

예: `@서비스` · `@˅서비스` → stem `서비스`

(현재 `tailWord`는 패턴 전체 문자열이라 `@서비스`와 `@˅서비스`는 **별도 등록**이다.)

## 혼재 · 표시 규칙 (확정 · 단일 규칙)

**등록 여부 게이트를 두지 않는다.** stem으로 hit를 모은 뒤:

```text
혼재 = (붙임 occurrence > 0) AND (띄움 occurrence > 0)
```

한쪽만 등록되면 반대쪽 occurrence는 구조적으로 0 → 혼재는 자동으로 false.  
한 슬롯만으로 반대 스타일을 추론하지 않는다.

### stem 요약 행 노출

| 조건 | 동작 |
|------|------|
| 해당 stem의 붙임+띄움 occurrence 합이 **≥ 1** | 요약 행 표시 (`붙임 N · 띄움 M`, 혼재면 라벨) |
| 해당 stem occurrence 합이 **0** | **요약 행을 렌더하지 않는다** (0·0 행을 만들지 않음) |

hit 없는 stem은 결과 리스트에 나타나지 않는 현재 동작과 맞춘다. 후속 필터 작업에서도 “빈 stem 행 유무”를 다시 묻지 않는다.

## glued / spaced 판정 (확정)

**1차 소스:** 패턴을 `phraseSlotPattern`과 동일한 토큰화로 읽어 **`space` 토큰이 하나라도 있으면 띄움**, 없으면 붙임.

**폴백:** 토큰화가 실패할 때만 `tailWord`를 `decodeSpacesVisible`한 뒤 공백(U+0020 / NBSP) 또는 원문에 ˅가 있으면 띄움, 아니면 붙임.

토큰화 결과와 문자열 휴리스틱이 어긋날 경우 **토큰화(1차 소스)를 따른다.**  
구현 시 tokenize 헬퍼를 phrase-slot 모듈에서 공유·export해 규칙 생성과 집계가 같은 정의를 쓰게 한다.

## 비목표 (1차)

- 슬롯 카드의 stem 아코디언 재그룹
- 미등록 반대 스타일 자동 스캔(본문 전수)
- DocSuffix · unify noise 와 공유 로직

## 구현 힌트 (구현 시 · 참고만)

- 집계: `patternKind === 'phrase-slot-find'` 인스턴스를 stem·glued|spaced로 분류 후 occurrence 합
- UI: `CheckResultsPanel` 공통 항목 결과 나열에서, 같은 stem 카드 블록 **앞**에 요약 행 삽입
- 테스트: stem 묶기 · N/M occurrence · 혼재 iff 양쪽 >0 · 편측만 있어도 요약은 나오되 혼재 없음 · occurrence 0이면 행 없음 · space 토큰 vs 폴백만 경로

## 성공 기준

- 같은 stem에 붙임·띄움 hit가 있을 때, 편집자가 **stem 요약 행 한 줄**로 N/M·(해당 시) 혼재를 한눈에 본다
- 결과 DOM/화면에서 해당 stem의 N/M·혼재 표시가 **정확히 1곳**(요약 행)에만 있다
- 표기통일 추천 목록·건수가 **변하지 않는다**

## 후속 (명시적 미룸)

- 혼재만 보기 필터
- 등록 안내(“띄움도 보려면 `@˅…`도 등록”)
- stem 아코디언으로 카드 재그룹 (베타에서 요약 행만으로 부족한지 확인 후)
- 베타 피드백 후 범위 재논의
