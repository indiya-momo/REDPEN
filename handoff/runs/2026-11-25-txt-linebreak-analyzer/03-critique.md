# 03 구현 관점 반론 (Grok)

대상: `02-design.md`. `src/` 미수정.

## 동의

- B 먼저가 맞다. C를 지금 열면 softwrap과 같은 “이득 미측정 구현”이 된다.
- merge·목록 확장·검수전 변경 금지는 구현 가능하고 범위가 좁다.

## 지적

1. **「육안 200을 TXT 픽스처로」는 공수가 새다.**  
   200 전부가 `paragraphJoinGlue` 입력으로 바로 쓰이지 않는다(레이아웃 keep).  
   **수정 제안:** 1차는 softwrap에서 이미 문자열만으로 판정 가능한 쌍 **15~30개**만 고른다 (Y/A/josa·midword). 200 전량은 게이트가 아님.
2. **성공 기준의 “합의 개수”가 비어 있다.**  
   **수정 제안:** 1차 최소 **n=20** (Y≥5, A≥10, josa/midword uncertain 유형 ≥5). 미달이면 테스트만 추가하고 런타임 금지 유지.
3. **UX 문구는 빼도 된다.** B의 핵심은 회귀다. 문구는 승인 범위를 넓힌다.  
   **수정 제안:** 1차 = 테스트(+필요 시 픽스처 JSON)만.
4. **`것|이었다` / `한|쪽으로`:** TXT에서 glue가 이미 `''`(붙임)인지 확인 후 픽스처화. 기대가 현행과 같으면 “회귀 잠금”이지 동작 변경이 아니다 — OK.

## 반영 권고 (설계 수정)

- 1차 범위: **회귀 테스트 n≈20**, UX 문구 제외.
- C 조건의 표본 n=100은 유지하되, B 승인과 분리.
- 그 외 02 결론(B 채택, C 보류, merge 금지) 유지.
